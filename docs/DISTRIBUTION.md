# הפצה לחברים

איך נותנים את האפליקציה לחבר, איך חותמים את הבנייה שהוא מקבל, ומה נשאר כמו שהיה במכשירים שלנו.

## הקישור

קישור אחד, קבוע, זהה לכולם:

    https://github.com/stevenbarzilay-cloud/Al-hasapa/releases/latest

הוא מוביל לעמוד הגרסה האחרונה, עם שתי הורדות מסומנות (לטלפון ול־Android TV) והוראות קצרות בעברית.
שני הקבצים נקראים תמיד באותו שם, ולכן גם הכתובות הישירות קבועות:

    https://github.com/stevenbarzilay-cloud/Al-hasapa/releases/latest/download/al-hasapa-phone.apk
    https://github.com/stevenbarzilay-cloud/Al-hasapa/releases/latest/download/al-hasapa-tv.apk

הקישור מיועד להתקנה בלבד. אין בו מזהה ספה, קוד צימוד, גיבוי או פרטי שחקנים, ופתיחתו במכשיר שהאפליקציה כבר מותקנת בו
לא משנה בו דבר (לא את ספת הבית ולא את החיבור הנוכחי).

בטלפון: «הספות שלי» ← «שליחת האפליקציה לחבר». האפליקציה בודקת קודם ששתי ההורדות באמת עונות, ורק אז מציגה
«✓ מוכן לשליחה» ופותחת את תפריט השיתוף של Android. כל עוד אין גרסה שפורסמה, היא אומרת שהקישור עוד לא מוכן.

## שני מפתחות חתימה, ולמה

Android מתקין עדכון רק אם הוא חתום באותו מפתח כמו מה שכבר מותקן.

- **המכשירים שלנו** (הטלפונים וה־TV שכבר מותקנת בהם האפליקציה) חתומים במפתח `app/debug.keystore`, שנמצא בריפו בכוונה
  (הוא ציבורי, לא סוד). הם ממשיכים להתעדכן בדיוק כמו עד היום, מהקבצים שב־`dist/`. שום דבר במסלול הזה לא השתנה:
  בלי משתני הסביבה של המפתח הפרטי, גם בניית release נחתמת במפתח הזה, כמו קודם.
- **החברים** מקבלים בנייה שחתומה ב**מפתח פרטי**, שלא נמצא בריפו ולא יהיה בו. הוא שמור כסוד ב־GitHub (Actions secrets),
  ורק ה־workflow `Release for friends` משתמש בו. כך אף אחד שמוריד את הריפו לא יכול לחתום עדכון שיותקן אצל חבר.

המשמעות המעשית: קובץ מהקישור הקבוע **לא יותקן מעל** האפליקציה שבמכשירים שלנו (Android יגיד שהחבילה מתנגשת), וזה בסדר:
המכשירים שלנו מתעדכנים מ־`dist/`. שני המסלולים בונים מאותו קוד, ומדברים זה עם זה כרגיל (צימוד, ביקור, תחרות סולו).

## פעם אחת: יצירת המפתח והסודות (הפעולות שלך)

צריך מחשב עם Java (JDK) או Android Studio, בשביל `keytool`.

1. במחשב, בתיקיית הריפו:

       bash tools/make-signing-key.sh

   הסקריפט שואל סיסמה, יוצר את הקובץ `~/couch-release.jks` (מחוץ לריפו), ומדפיס ארבעה ערכים.
   **שמרו את הקובץ ואת הסיסמה במקום בטוח** (מנהל סיסמאות, גיבוי). כל גרסה עתידית לחברים חייבת להיחתם באותו מפתח.

2. ב־GitHub: Settings ← Secrets and variables ← Actions ← New repository secret
   (`https://github.com/stevenbarzilay-cloud/Al-hasapa/settings/secrets/actions`), ומוסיפים ארבעה סודות:

   | שם | ערך |
   |---|---|
   | `COUCH_KEYSTORE_PASSWORD` | הסיסמה שבחרתם |
   | `COUCH_KEY_PASSWORD` | אותה סיסמה |
   | `COUCH_KEY_ALIAS` | `couch` |
   | `COUCH_KEYSTORE_B64` | השורה הארוכה שהסקריפט הדפיס (כולה) |

בלי סקריפט, אותו דבר ביד:

    keytool -genkeypair -v -keystore ~/couch-release.jks -storetype PKCS12 -alias couch \
      -keyalg RSA -keysize 4096 -validity 10950 -dname "CN=Al HaSapa"
    base64 < ~/couch-release.jks | tr -d '\n'      # זה הערך של COUCH_KEYSTORE_B64

## פרסום גרסה (גם הראשונה)

1. ב־GitHub: Actions ← **Release for friends** ← Run workflow (אפשר לכתוב שורה של «מה חדש»).
2. ה־workflow מריץ את הבדיקות, בונה את שתי האפליקציות, חותם במפתח הפרטי, מוודא שהן **לא** חתומות במפתח הציבורי של הריפו,
   מפרסם Release בשם `v<גרסה>` עם שני הקבצים `al-hasapa-phone.apk` ו־`al-hasapa-tv.apk`, ובסוף בודק ששתי הכתובות
   הקבועות עונות. רק אם הכול עבר, הריצה ירוקה, ובסיכום שלה כתוב שהקישור מוכן לשליחה.
3. מאותו רגע «שליחת האפליקציה לחבר» בטלפון מציגה «✓ מוכן לשליחה».

הרצה חוזרת על אותה גרסה מחליפה את הקבצים באותו Release. גרסה חדשה (אחרי שינוי `versionName`) יוצרת Release חדש,
והקישור הקבוע עובר אליו מעצמו.

## מה החבר עושה

ההוראות שהוא רואה בעמוד הגרסה נמצאות ב־`docs/RELEASE-NOTES.md`. בקצרה: מתקין בטלפון, בוחר «הקמת ספה משלי», נותן שמות;
מתקין בטלוויזיה (Downloader), בוחר «הצטרפות לספה קיימת», ובטלפון «הספות שלי» ← הטלוויזיה ← «לחבר אותה לספת הבית שלי» עם הקוד.
מאותו רגע יש לו ספה משלו, עם שחקנים, היסטוריה וניקוד משלה.

## אופציה לעתיד: מפתח אחד לכולם (סיבוב מפתח)

אפשר להעביר גם את המכשירים שלנו למפתח הפרטי בלי להסיר את האפליקציה, בעזרת «סיבוב מפתח» של Android (חתימה v3):
בנייה שחתומה במפתח הפרטי, עם הוכחה שהמפתח הישן מאשר אותו, מתקבלת כעדכון ב־Android 9 ומעלה.

    apksigner rotate --out lineage.bin \
      --old-signer --ks app/debug.keystore --ks-key-alias androiddebugkey --ks-pass pass:android \
      --new-signer --ks ~/couch-release.jks --ks-key-alias couch
    apksigner sign --ks app/debug.keystore --ks-key-alias androiddebugkey --ks-pass pass:android \
      --next-signer --ks ~/couch-release.jks --ks-key-alias couch \
      --lineage lineage.bin --rotation-min-sdk-version 28 al-hasapa-phone.apk

לא עשינו את זה כברירת מחדל, משתי סיבות. אחרי שמכשיר קיבל עדכון כזה הוא **לא יקבל יותר** בניות שחתומות רק במפתח הציבורי
(אלה שב־`dist/`), כלומר כל עדכון שלנו יצטרך לעבור דרך ה־workflow. והמפתח הישן ציבורי, כך שהסיבוב לא מוסיף הגנה למכשירים
שעוד לא עודכנו. אם תרצו לעבור למסלול אחד, זה שינוי קטן ב־workflow, ונעשה אותו יחד.
